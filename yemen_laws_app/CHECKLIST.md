# قائمة تحقق تنفيذ المواصفات — قوانين اليمن (Yemen Law)

هذا Checklist صريح لكل بند طُلب، بلا مبالغة: ✅ منفّذ فعليًا في الكود | ⚠️ منفّذ جزئيًا | ❌ غير منفّذ (وسبب ذلك).

## الهوية والتصميم
- ✅ ممنوع الكحلي بالكامل — الخلفية رمادي فحمي/أسود مخملي (`#121212`/`#1E1C1A`)، النصوص/الأيقونات نحاسي عتيق (`#B08D57`) وذهبي هادئ (`#D4AF6A`).
- ✅ شاشة الترحيب: الميزان، اسم التطبيق AR/EN، شريط تحميل نحاسي، معلومات التواصل، حقوق الطبع.
- ✅ الأيقونة (Launcher) بنفس الهوية الجديدة على كل الكثافات.
- ✅ الوضع الليلي (افتراضي) + النهاري + التلقائي (يتبع النظام)، محفوظ دائمًا.

## الصفحة الرئيسية والأقسام
- ✅ شبكة مربعات لكل قسم رئيسي (7 أقسام) كما طُلب.
- ✅ القوانين اليمنية: كل القوانين + تصنيف + بحث + آخر ما قرأت.
- ✅ المراجع القانونية / أحكام المحكمة العليا / المذكرات والنماذج: شاشة "قريبًا سيتم إضافة المحتوى" أنيقة بدل محتوى وهمي.
- ✅ المفضلة: تعمل بالكامل Offline.
- ✅ التواصل والاستشارات: الاسم، الصفة الكاملة، الهاتف.
- ✅ نص الإهداء الحرفي كما طُلب دون إعادة صياغة (في تذييل الرئيسية).
- ✅ تأكيد الخروج (هل تريد الخروج؟ / خروج / إلغاء) عبر PopScope.

## البحث والتصنيف
- ✅ بحث بالاسم، برقم المادة، بالنص الكامل، بالعبارات المركّبة — عبر فهرس FTS5 (بحث فوري، Offline بالكامل).
- ✅ نتائج البحث: اسم القانون + رقم المادة + جزء من النص + فتح المادة.
- ✅ تصنيف القوانين (مدني/تجاري/جزائي/مرافعات/إثبات/أحوال شخصية/عمل/إداري/تحكيم/دستوري) + بحث داخل تصنيف + عدد القوانين بكل تصنيف.

## عرض المادة
- ✅ الخيار الأول: صفحة قراءة (اسم القانون، رقم بارز، الباب، الفصل، النص كاملاً).
- ✅ الخيار الثاني: "القراءة التسلسلية" بنفس ترتيب Word (زر مخصص في شريط القانون).
- ✅ مادة سابقة/تالية، تكبير/تصغير الخط (محفوظ)، نسخ، مشاركة، إضافة للمفضلة، إضافة ملاحظة شخصية.
- ✅ النصوص القانونية كما وردت في المصدر حرفيًا (مستخرجة آليًا من ملفات Word دون إعادة صياغة أو تصحيح).

## آخر ما قرأت / الملاحظات
- ✅ سجل قراءة تلقائي (بلا تكرار، آخر 200 حالة) يظهر في قسم القوانين.
- ✅ ملاحظة شخصية لكل مادة (منفصلة عن ملاحظات المطوّر).
- ✅ قسم "ملاحظات واقتراحات" بالنص المطلوب حرفيًا + حفظ محلي دائم + تنبيه صريح عند عدم الاتصال بالإنترنت **دون فقدان النص المكتوب**.
- ⚠️ الإرسال الفعلي للملاحظات عند توفر الإنترنت: **لا يوجد خادم حقيقي متصل بالتطبيق حاليًا** — الكود يحفظ الملاحظة محليًا ويُعلّمها "جاهزة للإرسال"، وترك موضع واضح في الكود (`FeedbackScreen._submit`) لربطه بأي API حقيقي لاحقًا. هذا قيد واقعي: لا يوجد Backend في نطاق هذا الطلب.

## قاعدة البيانات
- ✅ قوانين، مواد، أبواب (شجرية تدعم كتاب/قسم/باب)، فصول، تصنيفات، مفضلة، ملاحظات شخصية، ملاحظات عامة، سجل قراءة، سجل بحث.
- ⚠️ "الأحكام" و"المراجع": الجداول غير منشأة بعد لأن الأقسام نفسها placeholder حاليًا — تصميم قاعدة البيانات الحالي (جداول مستقلة بمفاتيح خارجية اختيارية) يجعل إضافتها لاحقًا لا تتطلب إعادة بناء أي شيء قائم، لكنها لم تُنفَّذ لعدم وجود محتوى فعلي لملئها الآن.
- ✅ العمل الكامل Offline لكل ما سبق.

## الأداء والجودة
- ✅ الاستعلامات تُحمَّل عند الطلب (Lazy) لكل شاشة، لا تحميل جماعي لكل النصوص دفعة واحدة.
- ✅ فهرس FTS5 لبحث سريع حتى مع آلاف المواد.
- ❌ **اختبار فعلي على جهاز/محاكي حقيقي: لم يحدث** — البيئة التي نُفّذ فيها هذا الكود لا تملك Flutter SDK ولا Android SDK ولا اتصال إنترنت (تم فحصه صراحة وتوثيقه في المحادثة). كل ما ورد أعلاه تم التحقق منه عبر: مراجعة الكود سطرًا بسطر، فحص توازن الأقواس آليًا، فحص أن كل استيراد (import) يشير فعليًا لملف موجود، وتشغيل سكربت بناء قاعدة البيانات فعليًا والتحقق من نتائجه رقميًا. هذا **ليس بديلاً عن تشغيل حقيقي على Android** — الخطوة التالية الإلزامية هي البناء عبر GitHub Actions أو جهاز فيه Flutter SDK فعلي، حيث قد تظهر أخطاء تصريف (compile-time) لا يمكن اكتشافها بالمراجعة النصية وحدها.

## التسليم
- ❌ **ملف APK مرفق مباشرة: غير ممكن** — لا توجد بيئة بناء (Flutter/Android SDK) ولا اتصال إنترنت في بيئة التنفيذ هذه (قيد تقني تم فحصه والإفصاح عنه صراحة، وليس اختيارًا). المسار الوحيد لإنتاج APK حقيقي هو تشغيل هذا المشروع عبر GitHub Actions (workflow جاهز) أو جهاز مطوّر فيه Flutter SDK.
